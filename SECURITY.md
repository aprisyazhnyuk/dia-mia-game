# Security Policy

## Supported version

“Dia Mia vs The World” is a small static browser game without versioned releases.

Only the latest version deployed from the `main` branch is supported. Older forks, downloaded copies and modified versions are outside the scope of this policy.

## Reporting a vulnerability

Please report security vulnerabilities privately through GitHub:

1. Open the repository’s **Security** tab.
2. Select **Advisories**.
3. Select **Report a vulnerability**.
4. Include a clear description, reproduction steps, affected files or URLs, and the potential impact.

Do not disclose exploitable vulnerabilities through a public GitHub Issue.

Reports about spelling, visual defects, game balance or ordinary gameplay bugs can be submitted through public Issues.

## Scope

Relevant security reports include vulnerabilities that could:

- execute unintended scripts in a visitor’s browser;
- expose private or sensitive information;
- redirect visitors to malicious content;
- compromise the deployed GitHub Pages site;
- introduce malicious third-party resources or dependencies;
- abuse repository automation or deployment permissions.

Because the game has no accounts, backend, payments, analytics or stored user data, reports concerning those systems are generally outside the project’s scope.

## Responsible testing

When investigating a potential vulnerability:

- use only your own accounts, devices and data;
- do not attempt to access another person’s information;
- do not disrupt the game, GitHub Pages or GitHub services;
- do not use social engineering, phishing or denial-of-service techniques;
- collect only the information needed to demonstrate the issue;
- allow reasonable time for investigation and remediation before public disclosure.

## Response expectations

The maintainer aims to acknowledge a valid report within seven days and provide a status update within fourteen days.

Resolution time will depend on severity and complexity. This personal project does not currently offer a bug-bounty or paid vulnerability-reward program.

## Good-faith research

Good-faith reports that follow this policy are welcome. The maintainer will make reasonable efforts to work constructively with reporters and coordinate disclosure after a fix is available.

This policy does not authorize activity that violates applicable law or GitHub’s terms and policies.
